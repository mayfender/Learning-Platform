# Roles และลำดับการทำงาน

โปรเจกต์นี้ใช้ 2 role ที่เปิดใช้งาน และมีเจ้าของโปรเจกต์ (พ่อ) เป็นผู้ตัดสินใจสุดท้าย (ระบบใหม่ตั้งแต่ 2026-10-02)

| Role | AI Model | ไฟล์ | ผลงานหลัก | เก็บไว้ที่ |
|---|---|---|---|---|
| ผู้เชี่ยวชาญออกแบบการเรียนรู้ (Learning Designer) | Opus | [learning-designer.md](learning-designer.md) | Lesson Spec | `docs/lessons/` |
| Builder (UX/UI + Developer) | Sonnet | [builder.md](builder.md) | HTML single page ต่อบทเรียน (ออกแบบและสร้างเลย ไม่มี mockup) | `public/topics/<เรื่อง>/NN-<ชื่อ>.html` |

role เดิมที่ปิดใช้งาน (Software Architect, Developer, Tester, UX/UI Designer) ย้ายไปไว้ที่ [disabled/](disabled/) เพื่อใช้เป็นข้อมูลอ้างอิงมาตรฐานเท่านั้น ห้าม spawn เป็น role แยก งานของ role เหล่านั้นรวมอยู่ใน Builder แล้ว

แหล่งข้อมูลหลักที่ทุก role ต้องอ่าน: [docs/math-learning-plan.md](../docs/math-learning-plan.md)

## ลำดับการส่งต่องาน

```
พ่อ (เป้าหมาย / ผลการทดสอบของลูก)
   │
   ▼
Learning Designer ──► Lesson Spec ──► [พ่ออนุมัติ]
                                          │
                                          ▼
Builder ──► ออกแบบและสร้าง HTML single page เลย (ทำบน main ไม่มี mockup/branch/PR/เทสต์)
                                          │
                                          ▼
                          [พ่อทดสอบเอง] ──► [พ่อลองกับลูก]
                                          │
                                          ▼
                     ผลใช้งานจริง ──► กลับไปที่ Learning Designer (ปรับบทเรียน)
```

## กติกาการทำงานร่วมกัน

1. **แต่ละ role ทำเฉพาะงานของตัวเอง**
   - Builder ไม่เปลี่ยนวิธีสอน โจทย์ เฉลย หรือข้อความที่ Designer รับรอง
   - Learning Designer ไม่กำหนดเทคโนโลยี ไม่เขียนโค้ด
2. **เจอจุดที่ไม่ชัด ให้ถามกลับไปที่ต้นทาง อย่าเดาเอง** Builder ถาม Learning Designer ในเรื่องวิธีสอน ทุก role ถามพ่อในเรื่องเป้าหมายและตัวลูก (ผ่านผู้ประสานงาน)
3. **งานจัดเป็นเรื่อง (topic)** เช่น `addition` แต่ละเรื่องมีหลายหน้า HTML ชื่อไฟล์ขึ้นต้นด้วยเลขลำดับ (`01-...html`, `02-...html`) Lesson Spec ใน `docs/lessons/` ใช้ชื่อเรื่องและเลขลำดับเดียวกัน
4. **รูปแบบรหัส:** `<วิชา>-<ขั้นบนบันได 2 หลัก>` ถ้ามีหลายบทในขั้นเดียวกัน ให้เติม `-a`, `-b` (วิชา: `ADD` บวก, `SUB` ลบ, `MUL` คูณ, `DIV` หาร, `DX` แบบทดสอบวินิจฉัย)
5. **เปลี่ยนเอกสารที่อนุมัติแล้ว** ต้องบันทึกในหัวข้อ "ประวัติการแก้ไข" ท้ายเอกสาร
6. **อัปเดต [docs/STATUS.md](../docs/STATUS.md) ทุกครั้งที่งานเปลี่ยนสถานะ**
7. **ความถูกต้องของตัวเลขเป็นความรับผิดชอบร่วม** Designer ตรวจเฉลยเอง Builder คิดเฉลยใหม่เองก่อนส่ง พ่อทดสอบเป็นด่านสุดท้าย
8. **ไม่มี Tester และไม่มีเทสต์อัตโนมัติสำหรับหน้า HTML** พ่อทดสอบเอง ผู้ประสานงานตรวจเบื้องต้นด้วยการเปิดหน้าดู

## ผู้ประสานงาน

session หลักที่คุยกับพ่อเป็นผู้ประสานงาน: spawn agent ของ role ที่เปิดใช้งาน (Learning Designer, Builder) เมื่อ agent ทำเสร็จให้กลับมารายงานพ่อและรอคำสั่งต่อไป ไม่ส่งต่อเอง Builder ทำงานและ commit บน `main` ได้ตรงๆ (ยกเว้นการแก้ `src/`, `.github/`, config ซึ่งต้องผู้ประสานงานสั่ง) รายละเอียดอยู่ใน [CLAUDE.md](../CLAUDE.md)
