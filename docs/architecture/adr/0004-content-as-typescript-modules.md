# ADR-0004: เนื้อหาบทเรียนเป็นไฟล์ TypeScript ที่มี type กำกับ

- สถานะ: ยอมรับ
- วันที่: 2026-09-29

## บริบท
ต้องเพิ่มบทเรียนใหม่โดยแก้ engine ให้น้อยที่สุด (N8) และต้องตรวจเฉลยอัตโนมัติได้ (N5) บางบทต้องสุ่มโจทย์ตามกฎ (F7)

## ทางเลือก
| ทางเลือก | ข้อดี | ข้อเสีย |
|---|---|---|
| JSON/YAML | แยกจากโค้ดชัดเจน | ไม่มี type ตรวจตอนเขียน ต้องเขียน schema แยก และเขียนตัวสร้างโจทย์ไม่ได้ |
| เขียนเป็น React component ต่อบท | ยืดหยุ่นสูงสุด | เนื้อหาปนกับ UI ทดสอบยาก |
| **TypeScript module ที่เป็นข้อมูล** | มี type ตรวจ ใช้ตัวสร้างโจทย์ที่เป็นฟังก์ชันได้ ทดสอบง่าย | ต้องมีความรู้ TS เล็กน้อย (AI เป็นคนเขียน) |

## การตัดสินใจ
- ทุกบทเรียนเป็นไฟล์ `src/content/lessons/<รหัส>.ts` ที่ export object ตาม type `Lesson`
- แบบทดสอบวินิจฉัยอยู่ที่ `src/content/diagnostics/<รหัส>.ts` ตาม type `Diagnostic`
- ไฟล์เนื้อหาเป็นข้อมูลล้วน ห้าม import React ห้ามมี side effect
- โจทย์มี 2 แบบ
  - **คงที่:** ระบุโจทย์ เฉลย และตัวเลือกไว้เลย
  - **สุ่มตามกฎ:** อ้างถึง generator ใน `src/engine/generators/` พร้อมพารามิเตอร์ generator ต้องรับ seed เพื่อให้ผลซ้ำได้ในเทสต์
- **เฉลยต้องคำนวณได้จากตัวโจทย์** (เช่น `{ op: 'add', a: 8, b: 5 }`) เพื่อให้เทสต์คำนวณเทียบได้เอง ไม่ใช่แค่เทียบกับค่าที่พิมพ์ไว้
- ข้อความภาษาไทยอยู่ในไฟล์เนื้อหา ไม่อยู่ใน component
- ทะเบียนทักษะอยู่ที่ `src/content/skills.ts` (เช่น `add.bonds-10`) ใช้ร่วมกับระบบทบทวน

## ผลที่ตามมา
- เพิ่มบทเรียนใหม่ = เพิ่มไฟล์เนื้อหา 1 ไฟล์ + ลงทะเบียน ถ้าต้องมีกิจกรรมแบบใหม่ จึงเพิ่ม activity type ใน engine
- มีเทสต์รวมที่วนตรวจทุกบทเรียนอัตโนมัติ (ดู ADR-0007)
