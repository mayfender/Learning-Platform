### ไม่ทดสอบ / ทดสอบไม่ได้ในสภาพแวดล้อมนี้ (ไปอยู่ในเช็คลิสต์ของพ่อในรายงาน)

### หมายเหตุวิธีทดสอบเวลา

| ปริศนา | การ์ด 1–9 จับคู่ได้เฉพาะผลรวม 10 (คู่อื่นถูกปฏิเสธ); คำใบ้ 3 ขั้นตรง LS; เหลือ 5 → ถามและ "ดูเฉลย"; "ไว้ก่อน" ข้ามและบันทึก; แตะ-แตะและลาก |

## 6. สภาพแวดล้อม

- production: `npm run acceptance -- ADD-04` (build + preview `localhost:4173`) ตรวจครบ 3 project
- dev (StrictMode): `E2E_DEV=1 npm run acceptance -- ADD-04 --project=desktop` โดยเฉพาะ TC-E01/E03/E04 (นับ event) และ TC-R03
- ระหว่างเขียน/แก้เทสต์รันทีละ project: `--project=desktop`

## 7. ข้อสมมติของเทสต์ที่ spec ไม่ได้ระบุ (ถ้าไม่ตรงให้ปรับ helper จุดเดียวที่ `helpers/add04.ts` ไม่ใช่การลดเกณฑ์)

1. หน้าเริ่มครั้ง (`sitting-intro`) มีปุ่ม "ต่อไป: หน้าของลูก" หรือปุ่มที่ขึ้นต้นว่า "เริ่ม" (`enterLesson`); หน้าส่งเครื่องไปหน้าบันทึกของพ่อด้วยปุ่มที่ขึ้นต้น "ส่งเครื่อง"/"ให้พ่อ"/"เริ่ม"/"รับทราบ"/"เรียบร้อย" หรือ "ต่อไป"/"ไปเลย" (`advanceToParentNote`)
2. การ์ดหน้าหลักเป็นลิงก์ (`role=link`) ชื่อมีชื่อบทและบรรทัดรอง "ครั้งที่ n" อยู่ในลิงก์เดียวกัน
3. ข้อความ ack ของเช็คก่อนใช้ชุดเดียวกับ DX-ADD (ใช้ `expect.soft` เท่านั้น)
4. ตัวเลือกของฟอร์มบันทึกพ่อเป็น radiogroup/group หรือปุ่มที่มีข้อความตาม P8
5. ข้อเช็คก่อน c1–c3 มี `skillId = add.bonds-10` และ c4–c6 `add.make-10`; ข้อของ A1/A2/A3 มี `mode` = `see`/`fade`/`mind`
6. ผิดหลายครั้งใน A1 บันทึกเป็น `item.answered` ต่อครั้ง (`attemptNo` 1–3) และ `revealed: true` อยู่ที่ event ใดก็ได้ของข้อนั้น
7. `block.started` ของ A2/A3 ที่ทำซ้ำมี `seed` (Tech §4.4 "seed ของทุกรอบบันทึกใน block.started")
8. ตารางรายข้อของหน้าพ่อของบทใช้หัวข้อคอลัมน์ที่มีคำว่า ข้อ / โจทย์ / ถูก / เวลา / ในหัว / เข้าใจผิด (เหมือน DX-ADD §5.7)
9. กล่องหยุดของพ่อมีปุ่มที่ขึ้นต้น "หยุด" และ "ข้ามส่วนนี้" (เฉพาะ A, B, ท้าทาย, ฝึก) ปิดด้วย Escape ได้
