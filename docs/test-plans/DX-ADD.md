### หมายเหตุวิธีทดสอบเวลา (สำคัญ)
ความคล่องขึ้นกับเวลาเงียบ (3/4/5/15 วินาที) การรอจริงทำให้ช้าเกินไป จึงใช้ **นาฬิกาปลอมของ Playwright** (`page.clock`):
- `installClock` ก่อน `goto`, `pauseClock` หลังกด "เริ่มภารกิจ" แล้วเดินเวลาด้วย `tick(ms)` เท่านั้น ทำให้ความหน่วงของทุกข้อ = ค่าที่กำหนดเป๊ะ (ทดสอบขอบเกณฑ์ ≤ 3000 คล่อง / 3001 ไม่คล่อง ได้)
- ต้องเดินเวลาทีละช่วงตามขอบของ timer ในแอป (900 แล้ว 1650 สำหรับแฟลช) เพราะ timer ที่ตั้งต่อกันในแอปนับจากเวลา ณ ตอนที่ React render
- การ fade ของ CSS วิ่งตามเวลาจริง จึงรอ 250 ms จริงก่อนอ่านค่า opacity
- มีเคสที่ใช้เวลาจริงล้วน (ไม่มีนาฬิกาปลอม) เพื่อกันข้อผิดพลาดจากการจำลอง: TC-08 (วัดจังหวะแฟลชจาก MutationObserver), TC-61 (กดค้างโลโก้ 2 วินาที), TC-73, TC-80 (ทำครบ 20 ข้อ ~40 วินาที)
- WebKit ต้องรอสั้นๆ (40 ms จริง) หลังเดินเวลาปลอมก่อนอ่าน DOM

หมายเหตุการวิเคราะห์ spec
- แถว 5 ของ LS §7 ("กลุ่ม 5A ไม่ผ่าน หรือด่าน 5 ถูกข้าม") ในส่วน "ด่าน 5 ถูกข้าม" **ไม่มีทางเป็นจริงเป็นเงื่อนไขแรก** เพราะข้ามด่าน 5 ต้องถูกด่าน 4 ≤ 1 ข้อ ซึ่งทำให้ด่าน 4 เป็น low และถูกจับที่แถว 4 ก่อนเสมอ (เทสต์ S14/S15 ยืนยันว่าได้ขั้น 4/1 ไม่ใช่ 5) — ไม่ใช่บั๊ก บันทึกเป็นข้อสังเกตถึง Designer
- LS §4 กฎความสำคัญ ("แยกให้ครบ 10 → M7, ใช้เลขคู่ → M8, ปัดเลขให้กลม → M12") เขียนเป็นกฎทั่วไป แต่ตารางรายข้อเขียนเงื่อนไข "ถ้าเลือก…" เฉพาะบางคำตอบ (และ Tech Spec D11 ตัดสินให้ใช้ตารางตามตัวอักษร) แผนนี้ใช้ตารางตามตัวอักษร เช่น 4.1 ตอบ 14 กับ `doubles` = M5 (ไม่ใช่ M8) ถ้า Designer ต้องการตามกฎทั่วไปต้องแจ้ง (คำถาม Q2)
