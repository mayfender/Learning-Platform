## 3. อุปกรณ์จำลองและ UI

ใช้ชุดเดิมให้มากที่สุด: ต่อยอด `TenFrame` และ `NumberBond` (ตาม ADR-0005) เพิ่มชิ้นเดียวที่ต้องใหม่จริงคือกองจุด/กระดานลาก และการ์ดสำหรับปริศนา ทุกชิ้นใช้ `ManipulativeBaseProps` เดิม

### 3.1 `TenFrame` v2 (ต่อยอด `src/manipulatives/TenFrame.tsx`)

ของเดิมไม่เปลี่ยน (DX-ADD ยังใช้ `filled`, `colorMode`, แฟลช, `hidden` ตามเดิม เทสต์เดิมต้องผ่านโดยไม่แก้)

```ts
export type CellState = 'empty' | 'dot' | 'added';

export interface TenFrameProps extends ManipulativeBaseProps {
  filled: number;                                   // เดิม: จุดตั้งต้น เติมตาม index 0..filled-1 (แถวบนซ้าย→ขวา แล้วแถวล่าง)
  colorMode?: 'single' | 'split-5';                 // เดิม: สีของจุดตั้งต้น
  added?: readonly number[];                        // ใหม่: index ช่องที่ "เติมเพิ่ม" สีใหม่; ต้องอยู่ในช่วง filled..9 และไม่ซ้ำ ผิด → throw ใน dev
  highlight?: { indices: readonly number[]; pulse?: boolean };   // ใหม่: วงแหวนรอบช่อง (feedback); pulse = กะพริบ
  onCellTap?: (index: number, state: CellState) => void;        // ใหม่: เรียกเมื่อ interactive และแตะช่องใดก็ได้ (component ไม่เปลี่ยนค่าเอง ผู้เรียกตัดสิน)
}
```
- ควบคุมจากภายนอกทั้งหมด (controlled) ผู้เรียกเก็บ `added` เอง
- สีจุด: `dot` ตาม `colorMode`; `added` ใช้ token ใหม่ **`--color-dot-added`** (light `var(--color-highlight)`, dark `var(--color-highlight)`) วาดพร้อมเส้นขอบ 2px สี `--color-on-highlight` เพื่อไม่พึ่งสีอย่างเดียว ต้องต่างจาก `--color-group-a` และ `--color-group-b` ชัดเจนทั้ง light/dark
- ไฮไลต์เป็น `<rect rx>` วงแหวนสี `--color-text` หนา 3px (pulse = opacity สลับ 0.4–1 ทุก 600 ms) reduced motion → วงแหวนคงที่ไม่กะพริบ
- ทุกช่องมี `data-cell-index` และ `data-cell-state`; จุดเป็น `<circle data-dot>`; **พื้นที่แตะและวงแหวนห้ามเป็น `<circle>`** (เทสต์นับจุดจาก `circle`)
- `interactive={true}`: แต่ละช่องมีพื้นที่แตะเต็มช่อง (`<rect>` โปร่งใสขนาดช่อง 40 หน่วย) ใช้ Pointer Events, `role="button"`, `tabIndex=0`, Enter/Space เท่ากับแตะ, `aria-label="ช่องที่ {i+1} ว่าง|มีจุด|เติมแล้ว"` ไม่ interactive → `role="img"` เดิม (label ห้ามบอกจำนวนจุดเมื่อใช้ในแฟลช)
- **ขนาดแตะ ≥ 48px:** ช่อง 40 หน่วยของ viewBox กว้าง 220 → ต้องเรนเดอร์กว้าง ≥ 264px เมื่อ `interactive` จึงบังคับ `size` เป็น `md` หรือ `lg` เท่านั้น (`sm` + `interactive` → throw ใน dev) ที่จอ 360px ได้ประมาณ 328px (ช่อง ≈ 59px)
- แฟลช/เวลา/reduced motion เหมือนเดิมทุกประการ (ดึงตัวจับเวลาเป็น hook `useFlash(mode, flashMs, onFlashEnd)` ใน `manipulatives/useFlash.ts` ให้ `MakeTenBoard` ใช้ร่วม พฤติกรรมของ `TenFrame` ต้องไม่เปลี่ยน)
- ดึงส่วนวาดช่องเป็น `<g>` ภายใน (`manipulatives/parts/TenFrameGrid.tsx`) เพื่อให้ `MakeTenBoard` ใช้ซ้ำ

### 3.2 `NumberBond` (สร้างใหม่ตาม ADR-0005: "แยกเลข")

```ts
export type BondSlot = number | '?' | null;   // null = ยังไม่ปรากฏ (ที่ว่างเว้นไว้ ไม่วาดวงกลม), '?' = วงประ

export interface NumberBondProps extends ManipulativeBaseProps {   // mode: 'show' | 'hidden' เท่านั้น ('flash' → throw ใน dev)
  whole: BondSlot;
  parts: readonly [BondSlot, BondSlot];
  highlight?: 'whole' | 'part-a' | 'part-b' | null;    // กะพริบตอนตอบถูก (reduced motion → วงแหวนคงที่)
}
```
- ผัง: วงกลม `whole` อยู่บน วงกลม `parts` สองวงอยู่ล่างซ้าย/ขวา เส้นเชื่อม (แบบต้นไม้) ขนาดตามความกว้างที่ให้ (≥ 96px)
- ค่าเปลี่ยนได้ตลอดเมื่อผู้เรียกส่งค่าใหม่ (นับขึ้นตามที่ลูกแตะ) การปรากฏของช่อง `null → ค่า` ใช้ fade 200 ms (ปิดเมื่อ reduced motion)
- a11y: `role="img"`, `aria-label` = `แยกเลข ทั้งหมด {whole} ส่วนที่หนึ่ง {a} ส่วนที่สอง {b}` (`?` อ่านว่า "ยังไม่รู้", `null` ไม่กล่าวถึง)
- ใช้ใน 2 รูป (ตรง LS §4)
  - A1: `whole=10`, `parts=[n, k]` โดย `k` = จำนวนช่องที่แตะ (`'?'` เมื่อยังไม่แตะ) → "n | ? | 10"
  - B1: `whole=b` (กองเดิม), `parts=[ย้าย, เหลือ]` → "b → (ที่ย้าย) + (ที่เหลือ)" `เหลือ` เป็น `'?'` จนตอบขั้น 2

### 3.3 `MakeTenBoard` และ `DotPile` (ใหม่: `src/manipulatives/`)

กล่อง 10 ช่องที่มีจุดตั้งต้น `a` จุด กับกองจุด `b` จุดข้างๆ ใช้ใน B1, B2, B3, B4 (แฟลชพร้อมกัน ลากจุดจากกองเข้ากล่อง)

```ts
export interface MakeTenBoardProps extends ManipulativeBaseProps {   // mode: show | flash | hidden
  boxDots: number;                       // 1..9 จุดตั้งต้นในกล่อง (split-5)
  pileDots: number;                      // 1..9 จุดในกองตอนเริ่ม
  moved: readonly number[];              // index ช่องที่จุดจากกองถูกย้ายมาแล้ว (controlled; ต้องเป็นช่องที่ ≥ boxDots และไม่ซ้ำ)
  highlight?: { target: 'gap' | 'pile-rest' | 'moved' | 'box'; pulse?: boolean } | null;
  onMove?: (cellIndex: number) => void;  // ลูกย้ายจุด 1 จุดเข้าช่อง (component ไม่เปลี่ยน moved เอง)
  onMoveRejected?: (why: 'outside' | 'full') => void;   // ปล่อยนอกกล่อง หรือกล่องเต็มแล้ว (ใช้บันทึก manip.rejected)
}
```
- `flashMs` ของบทนี้ = 2000 (B3) ผ่าน `useFlash` ตัวเดียว: **กล่องและกองแสดง ซ่อน และเริ่ม fade พร้อมกันในเฟรมเดียว** (SVG เดียว opacity เดียว) เวลาและ reduced motion ตามกฎแฟลชเดิม `onFlashEnd` ครั้งเดียว
- ภาพเป็น **SVG เดียว** viewBox กว้าง 220: กล่อง (ใช้ `TenFrameGrid`) อยู่บน กองอยู่ล่าง วางเป็น 2 แถวๆ ละ 5 ตำแหน่งโดยไม่มีเส้นช่อง (เพื่อไม่ให้เหมือนกล่องที่ 2) จุดกองและจุดที่ย้ายแล้วใช้สี `--color-dot-added` เหมือน "เติมเพิ่ม" ของ A1 (สื่อว่า "เอามาเติม") จุดตั้งต้นในกล่องใช้ split-5
- `hidden`: การ์ดเปล่าขนาดเท่าเดิมทั้งภาพ (กล่อง + พื้นที่กอง) ไม่ขยับ layout
- **การย้าย (2 ทางเสมอ)**
  1. **ลาก:** Pointer Events บนจุดกอง (`touch-action: none` เฉพาะจุดนั้น, `setPointerCapture`, ลากเกิน 4px ถือว่าลาก) มีเงาจุดตามนิ้ว ปล่อยเหนือกล่อง (กรอบกล่อง + ขอบ 12 หน่วย) → `onMove(nearestEmptyCell)` (ช่องว่างที่ใกล้จุดปล่อยที่สุด ปล่อยบนช่องที่มีจุดแล้วก็ได้ ระบบเลือกช่องว่างที่ใกล้ที่สุดให้) ปล่อยนอกกล่อง → จุดกลับกอง + `onMoveRejected('outside')` (animation กลับ 200 ms; reduced motion กลับทันที)
  2. **แตะช่องว่างในกล่อง:** ย้ายจุดจากกอง 1 จุดเข้าช่องนั้น (สำหรับนิ้วเล็ก/มือถือ และผู้ที่ลากไม่ถนัด) เรียก `onMove(index)` เหมือนกัน
  - กล่องเต็ม (ไม่มีช่องว่าง) → ไม่ย้าย, `onMoveRejected('full')`; กองหมด → แตะช่องว่างไม่มีผล
  - ไม่มีการลากจุดออกจากกล่อง (ย้ายแล้วล็อก)
- ขนาดแตะ: จุดกองมีพื้นที่แตะโปร่งใส `<rect>`/`<g>` รัศมีเทียบ ≥ 20 หน่วย (≥ 48px เมื่อกว้าง ≥ 264px) จุดกองห่างกัน ≥ 40 หน่วย; ห้ามใช้ `<circle>` เป็นพื้นที่แตะ (นับจุด)
- geometry แยกเป็นฟังก์ชัน pure ใน `manipulatives/geometry.ts` เพื่อเทสต์ใน jsdom (`getScreenCTM` ไม่มีใน jsdom): `cellCenter(i)`, `pointToCell(x, y)`, `nearestEmptyCell(x, y, occupied)`, `isInsideBox(x, y)`, `pileSlot(i)`; ตัวแปลงพิกัดหน้าจอ→viewBox อยู่ใน component และทดสอบด้วย e2e

### 4.4 กฎสร้างโจทย์ (ฝึกให้คล่อง, ทบทวน, ทำซ้ำ)

Generator รับ seed (ADR-0004) `engine/rng.ts`: `createRng(seed: number)` (mulberry32) → `{ next(): number; int(min, max); shuffle<T>(xs): T[]; pick<T>(xs): T }` `seed` ของทุกรอบบันทึกใน `block.started` เพื่อทำซ้ำได้

**`generateBondsRound(seed, opts?: { avoid?: readonly BondsItemKey[] })` → 4 ข้อ** (LS §6 ชุด bonds)

| เงื่อนไข | ค่า |
|---|---|
| ค่า n | 1–9, **ไม่ซ้ำกันในรอบ** |
| n = 5 | ปรากฏ **ไม่เกิน 1 ข้อ** และเข้าตัวเลือกเมื่อ `rng.next() < 0.2` (ให้ปรากฏได้น้อย) |
| รูปแบบ | 2 ข้อ **แฟลช** (`missing-part` ว่างกี่ช่อง, flow `silent-flash-gap`) + 2 ข้อ **ตัวเลข** (flow `silent-text`) |
| ตัวเลข 2 ข้อ | 1 ข้อ `n + ? = 10` (`missing: 'second'`) และ 1 ข้อ `? + n = 10` (`'first'`) |
| ลำดับข้อ | สลับ (shuffle) แต่แฟลช 2 ข้อไม่ติดกันทั้งคู่ต้นรอบ (ไม่บังคับ ปล่อยสุ่ม) |
| หลีกเลี่ยงซ้ำ | ไม่มีข้อที่ (n, รูปแบบ) เท่ากับข้อใน `avoid` (ข้อของรอบก่อน) ถ้าเลือกไม่ได้ให้ยอมซ้ำ n แต่รูปแบบต่าง |
| เฉลย | `10 − n` คำนวณจาก `solve(problem)` |

**`generateMakeTenRound(seed, opts?: { avoid?: readonly [number, number][] })` → 4 ข้อ** (LS §6 ชุด make-ten)

| เงื่อนไข | ค่า |
|---|---|
| a, b | 2–9 |
| ผลรวม | 11 ≤ a + b ≤ 18 |
| a ≠ b | บังคับ |
| ลำดับตัวตั้ง | **2 ข้อตัวใหญ่ก่อน (a > b) และ 2 ข้อตัวเล็กก่อน (a < b)** |
| ความหลากหลาย | คู่ไม่ซ้ำกันในรอบ (นับ {a,b} กลับด้านเป็นคู่เดียวกัน) และไม่ตรงกับ `avoid` |
| รูปแบบ | flow `silent-text` (ตัวเลขล้วน) |
| เฉลย | `a + b` |

**ชุดตัวเลขใหม่สำหรับทำซ้ำตาม LS §9 (Designer รับรองแล้ว Q4)**
- `generateA2Retry(seed, avoid)`: 6 ข้อ n ∈ 1..9 ยกเว้น 5 ไม่ซ้ำกัน **ต้องมี n ที่ไม่เคยอยู่ในชุดเดิมให้ครบ** (ชุดเดิมมี 6, 2, 8, 3, 1, 7 ดังนั้นชุดใหม่ต้องมี 4 และ 9) และลำดับต่างจากชุดเดิม
- `generateA3Retry(seed, avoid)`: 6 ข้อ กฎเดียวกับ A3 เดิม (n ไม่ซ้ำ, 1..9 ยกเว้น 5, ตำแหน่งที่หายสลับ ครึ่ง/ครึ่ง) ต้องมี n ที่ไม่เคยอยู่ในชุด A3 เดิมครบ (ชุด A3 เดิมมี 7, 4, 8, 3, 6, 9 ดังนั้นชุดใหม่ต้องมี 1 และ 2) และลำดับต่างจากชุดเดิม
- `generateB3Retry(seed, avoid)` และ `generateB4Retry(seed, avoid)`: 6 ข้อ กฎ make-ten ข้างบน (a,b 2–9, 11 ≤ a+b ≤ 18, a ≠ b) คู่ไม่ซ้ำกับชุดเดิมของ B3/B4; B3 ข้อ 1–3 สามช่อง 4–6 ช่องเดียวเหมือนเดิม
- ตรวจ: เฉลยจาก `solve` / `makeTenPlan` ทุกข้อ

**เทสต์ N5 (unit, `engine/generators/*.test.ts`)** — สุ่ม **≥ 500 seed ต่อ generator** แล้วตรวจเงื่อนไขทุกแถวในตารางด้านบนโดยไม่พึ่งการคำนวณของ generator เอง (ตรวจด้วยฟังก์ชันอิสระในเทสต์) และ
- deterministic: seed เดียวกันได้รอบเดียวกัน
- ทุกข้อ: เฉลยจาก `solve(problem)` ตรงกับ `expected`; ผล `makeTenPlan` ทุกข้อของ make-ten มี `gap ≥ 1`, `rest ≥ 1`, `boxDots + gap = 10`, `gap + rest = pileDots`
- ทุก 4 ข้อของ bonds มีแฟลชพอดี 2 และตัวเลขพอดี 2 (ตำแหน่งที่หาย first 1 second 1), `n=5` ปรากฏ ≤ 1 และปรากฏจริงในบาง seed (ไม่ใช่ 0 เสมอ) กับไม่ปรากฏในส่วนใหญ่
- ตัวอย่างโจทย์ 13 ข้อใน LS §6 เป็นตารางทดสอบ: `solve` ตรงเฉลยที่ LS เขียน และแต่ละข้ออยู่ในเงื่อนไขของ generator (สร้างได้ในทฤษฎี)

### 4.5 กฎจับคู่ความเข้าใจผิด (`engine/lesson/classify.ts`)

กฎ LS §2 เป็นฟังก์ชันของ "โจทย์ + คำตอบ" (ไม่ใช่ตารางรายข้อ เพราะโจทย์ฝึกสุ่ม)

```ts
export type LessonMisconception = 'L1' | 'M4' | 'M5' | 'M6' | 'M7' | 'MX';
export type AnswerKind = 'gap' | 'rest' | 'total';
export function classifyLessonAnswer(
  kind: AnswerKind, problem: Problem, response: number, opts?: { mindView?: StrategyId },
): { correct: boolean; misconceptionId?: LessonMisconception };
```

**`gap` — ช่องว่างของกล่อง** (c1–c3, A1–A3, bonds ฝึก/ทบทวน/ท่องซ้ำ, ช่อง "ขาด" ของ B1/B3) ให้ `n` = จำนวนที่เห็นในกล่อง/โจทย์ (`missing-part`: `part`; `arith`: `max(a,b)`) `e = 10 − n`

| ลำดับตรวจ | เงื่อนไข | ผล |
|---|---|---|
| 1 | `response === e` | ถูก |
| 2 | `response === n` | L1 |
| 3 | `response === 10 + n` | M4 |
| 4 | `\|response − e\| === 1` | M5 |
| 5 | อื่นๆ | MX |

(ตรวจแล้ว: สำหรับ n = 1–9 เงื่อนไข 2–4 ไม่ทับกันเลย และไม่ทับกับเฉลย)

**`total` — ผลรวมของบวกข้ามสิบ** (c4–c6, ขั้นผลรวมของ B1/B3, B4, make-ten ฝึก/ทบทวน) `s = a + b`

| ลำดับตรวจ | เงื่อนไข | ผล |
|---|---|---|
| 1 | `response === s` | ถูก |
| 2 | `response === s − 10` | M6 |
| 3 | `response ∈ {s − 1, s + 1}` **และ** `response ∈ {10 + a, 10 + b}` | **ชนกัน** (ดูด้านล่าง) |
| 4 | `response ∈ {s − 1, s + 1}` | M5 |
| 5 | `response ∈ {10 + a, 10 + b}` | M7 |
| 6 | อื่นๆ | MX |

- **ชนกันเกิดเฉพาะเมื่อตัวบวกตัวหนึ่งเป็น 9 และตอบ s + 1** (เช่น 9+6 ตอบ 16 = 10+6) LS §2 เขียน M5 ก่อน M7 และไม่ระบุกรณีชน **Designer ตัดสินแล้ว (Q1)** ตามหลักเดียวกับกฎของ DX-ADD ที่ Designer อนุมัติแล้ว: ให้คำบอกเล่าของลูกตัดสินก่อน): **ชนกัน → M7 ถ้า `mindView === 'see-box'` (ลูกบอกว่าเห็นกล่อง 10 ช่อง) ไม่งั้น M5** ที่ขั้นของ B1/B3 ที่ไม่มีคำถามในหัวเห็นอะไร → M5 เพราะ M7 กับ M5 ให้ผลต่างกัน (M7 รีเซ็ตกล่อง Leitner ส่วน M5 ไม่รีเซ็ต)
- การจัดประเภทข้อที่ถาม "ในหัวเห็นอะไร" เกิดหลังได้คำตอบของ mind view (pending แล้วตัดสินตอนเลือก เหมือนข้อถามวิธีคิดของ DX-ADD) ข้อที่ mind view ไม่บังคับและลูกข้าม → `mindView` ว่าง

**`rest` — ที่เหลือในกอง** (ขั้น 2 ของ B1 และช่อง "เหลือ" ของ B3) ใช้ `makeTenPlan(a,b)`: `e = rest`, `pile = pileDots`

| ลำดับตรวจ | เงื่อนไข | ผล |
|---|---|---|
| 1 | `response === e` | ถูก |
| 2 | `response === pile` (ไม่หักส่วนที่ย้ายไป) | M7 |
| 3 | `\|response − e\| === 1` | M5 |
| 4 | อื่นๆ | MX |

- LS §2 ไม่ได้ระบุกฎของขั้น "เหลือ" ตรงๆ แต่ M7 ("ไม่หักส่วนที่ใช้เติม") ตรงกับการตอบจำนวนกองเดิมพอดี จึงเสนอให้ขยายกฎ M7 มาที่ขั้นนี้ (ตรงกับข้อความ feedback ของ M7 ใน LS §4 B1 ที่พูดถึงกอง) ทับกับ M5 ได้เมื่อ `gap = 1` (`pile = e + 1`) → ให้ M7 มาก่อน (ลำดับ 2 ก่อน 3) เพราะตรงนิยามของ M7 โดยโครงสร้าง

**ตารางเทสต์แยกรายรูปแบบ** (`classify.test.ts` พิมพ์ค่าจาก LS §2 และ §4 โดยตรง ห้าม import จากเนื้อหา) — ทุกแถวต้องมีเทสต์:

| รหัส | kind | โจทย์ | คำตอบ → ผล |
|---|---|---|---|
| L1 | gap | แฟลช 7 จุด (`missing-part` part 7) | 7 → L1; 9 (part 9) ตอบ 9 → L1; `? + 4 = 10` ตอบ 4 → L1; 8+5 ช่อง "ขาด" ตอบ 8 → L1 |
| M4 | gap | `7 + ? = 10` | 17 → M4; `? + 4 = 10` ตอบ 14 → M4; part 9 ตอบ 19 → M4 |
| M5 | gap | `7 + ? = 10` | 2, 4 → M5; part 9 (เฉลย 1) ตอบ 0 และ 2 → M5 (0 ต้องเป็น M5 ตามกฎ ±1) |
| M5 | rest | 8+5 (เหลือ 3) | 2, 4 → M5 |
| M5 | total | 8+5 | 12, 14 → M5; 4+7 ตอบ 10, 12 → M5 |
| M6 | total | 8+5 | 3 → M6; 9+7 ตอบ 6 → M6; 4+7 ตอบ 1 → M6 |
| M7 | total | 8+5 (s=13) | 15, 18 → M7 (ไม่ชน M5 เพราะ M5 คือ 12, 14); 9+7 (s=16) ตอบ 19 (10+9) → M7 (17 = 10+7 อยู่ในแถว "ชนกัน"); 7+4 (s=11) ตอบ 14, 17 → M7 |
| M7 | rest | 8+5 | 5 → M7; 9+6 (เหลือ 5) ตอบ 6 → M7 (ไม่ใช่ M5) |
| ชนกัน | total | 9+6 (s=15) ตอบ 16 | ไม่มี mindView → M5; `see-box` → M7; `count-fingers`, `count-in-head`, `see-number`, `unsure` → M5 · 6+9 ตอบ 16 เหมือนกัน · 9+7 (s=16) ตอบ 17 เหมือนกัน |
| MX | ทุก kind | — | 99 → MX; 0 (kind total 8+5) → MX; เฉลย + 2 → MX |
| ถูก | ทุก kind | — | เฉลย → `correct: true` ไม่มีรหัสไม่ว่า mindView อะไร |

**เทสต์แบบ exhaustive (property):** วนทุก (a, b) ที่ 2–9, 11 ≤ a+b ≤ 18 และทุก `response` 0–999: ผลต้องเป็นค่าเดียวเสมอ (deterministic); ผล `correct: true` ⇔ `response === s`; ชนกัน (`s+1 ∈ {10+a,10+b}` หรือ `s−1`) เกิดเฉพาะกรณีมีตัวบวก 9 และตอบ s+1 เท่านั้น (ยืนยันข้ออ้างข้างบน); ทุกค่าของ M6 = `s − 10` ≥ 1; ไม่มีรหัสอื่นนอก L1, M4, M5, M6, M7, MX ทำนองเดียวกันสำหรับ `gap` (n 1–9, response 0–999) และ `rest` (ทุก a,b ที่ผ่านเงื่อนไข)

### 4.6 ปริศนา "ใบไหนไม่มีคู่" (LS §7)

```ts
challenge: {
  cards: [1,2,3,4,5,6,7,8,9],
  target: 10,
  hints: ['เริ่มจากการ์ด 9 ก่อน 9 ต้องคู่กับอะไร', 'จับคู่ 9, 8, 7, 6 ก่อน (แต่ละใบใกล้ 10 กว่า) แล้วดูว่าเหลืออะไร', 'ลอง 5 คู่กับ 5 ได้ไหม มีการ์ด 5 กี่ใบ'],   // LS §7 คำใบ้ขั้น 1–3 ตรงตัวอักษร
  answer: { leftover: 5, pairs: [[1,9],[2,8],[3,7],[4,6]], explanation: 'คู่ที่ได้คือ 1+9, 2+8, 3+7, 4+6 เหลือใบ 5 เพราะ 5+5 = 10 แต่มีการ์ด 5 แค่ใบเดียว ไม่มีอีกใบมาคู่' },
}
```
- ลูกจับคู่ได้เฉพาะผลรวม 10 (ผลรวมอื่นถูกปฏิเสธ) การ์ดที่จับแล้วจางลง ไม่มีการคืนคู่ไม่ได้ (มีปุ่ม "เริ่มใหม่" ล้างทั้งหมด)
- ปุ่ม "ขอคำใบ้" แสดงคำใบ้ทีละขั้น (1 → 2 → 3) นับจำนวนที่ใช้
- เมื่อจับครบ 4 คู่ (เหลือ 1 ใบ) ขึ้นคำถาม "ใบไหนที่เหลืออยู่ แล้วทำไม" ลูกแตะการ์ดที่เหลือเพื่อยืนยัน ส่วน "ทำไม" **ให้เล่าให้พ่อฟัง** (ไม่พิมพ์) แล้วกด "ดูเฉลย" จึงแสดง `explanation` — ไม่ตัดสินคำอธิบายด้วยระบบ
- คำถามต่อยอด "ถ้ามีการ์ด 1–10" (LS §7) ไม่อยู่ในจอ ใส่ในหน้าพ่อ (`parentGuide.challengeExtension` พร้อมเฉลยของ LS: เหลือ 5 และ 10)
- ข้ามได้: หน้าเปิดปริศนามีปุ่ม "ลองเลย" และ "ไว้ก่อน" (บันทึกเป็นข้าม `skipReason: 'manual'`)

## 5. ลำดับการทำงานและ state

### 5.1 ครั้ง (sitting) และส่วน (block)

- ครั้งที่ 1 และ 2 กำหนดในเนื้อหา (`sittings`) ปลายครั้งมี "ส่งเครื่องให้พ่อ" → บันทึกของพ่อ (§5.7) → จบครั้ง
- **block** = 1 ชุดของกิจกรรม: `check`, `A`, `B`, `practice` (1 รอบต่อทักษะ), `challenge` และนอกบท `review`, `drill` การรันแต่ละ block มี `blockId` (UUID) ผูกกับ `item.answered` ทุกข้อ (ADR-0008, §6)
- **ความก้าวหน้าไม่เก็บเป็นสถานะ ให้คำนวณจาก event log ทุกครั้ง** (`deriveProgress(lesson, events)` — pure) แล้ว `planSitting(lesson, progress, now)` บอกว่าครั้งนี้ต้องทำ block ไหนบ้าง (พร้อมข้ามอะไร ชุดตัวเลขใหม่ seed เท่าไร) ผลคือปิดแอปกลางทางแล้วกลับมาก็เริ่มที่ block ที่ยังไม่จบ (block ที่ไม่จบเริ่มใหม่ทั้ง block ข้อที่ตอบไปแล้วยังอยู่ใน log แต่ไม่นับในผลผ่าน/ไม่ผ่าน เพราะ block นั้นไม่มี `block.completed`)
- ตัวเล่น: route `/play/ADD-04` (`Play` หา `lessons[activityId]` → `LessonPlayer`), `/review` (`ReviewPlayer`), `/drill` (`DrillPlayer`)

### 5.2 ลำดับหน้าจอต่อชนิดข้อ (flow)

ทุกการแตะที่เปลี่ยนหน้าจอของลูกผ่าน `useTapGuard` (400 ms); เวลาเงียบวัดเหมือน DX-ADD (เริ่มตอนรับคำตอบได้: ข้อแฟลช = หลังภาพซ่อน, ข้ออื่น = ตอนแสดงโจทย์และแป้นใช้ได้; หยุดตอนกด "ตอบ"; ซ่อนแท็บระหว่างตอบ → `latencyValid: false`) ห้ามแสดงเวลาใดๆ

| flow | ลำดับหน้า | ตอบผิด | จบข้อ / emit |
|---|---|---|---|
| `silent-flash-gap` | ready ("พร้อมนะ..." 900) → show (แฟลชกล่อง n จุด 1500 พร้อม "ดู!") → answering (ซ่อนพร้อม "ซ่อนแล้ว! ว่างกี่ช่องนะ?" — ข้อความ LS §4 A2; ในเช็คก่อนและรอบฝึกใช้ข้อความเดียวกัน) → ack 1000 → (คำถามในหัวเห็นอะไร ถ้ามี) → ข้อถัดไป | ไม่บอก | emit `item.answered` ตอน SUBMIT (ไม่มีคำถามในหัว) หรือหลังเลือก (มี) |
| `silent-text` | โจทย์ตัวเลข → answering → ack 1000 → (คำถามในหัว ถ้ามี) → ข้อถัดไป | ไม่บอก | เหมือนข้างบน |
| `guided-fill` (A1) | หน้าเดียว: กล่อง n จุด (split-5) แตะช่องว่างได้ + `NumberBond` `[n, k\|?, 10]` + คำถาม "เติมอีกกี่ช่องถึงจะเต็ม" + แป้น | ดู §5.2.1 | ตอบถูก → ข้อความถูก (LS) + เติมช่องว่างที่เหลือเป็นสี "เติมเพิ่ม" กะพริบส่วนที่เติมทั้งหมด + bond เป็น `[n, x, 10]` → "ต่อไป" |

| `mind-gap` (A3) | โจทย์ตัวเลข → answering → "ในหัวเห็นอะไร" (5 ตัวเลือก LS) → [เลือก "นับนิ้ว" → ข้อความ LS ตรงตัวอักษร] → [ตอบผิด → กล่อง n จุด + ไฮไลต์ช่องว่าง + `ลองนึกกล่อง 10 ช่องที่มี {n} จุด`] → "ต่อไป" (มีเมื่อมีข้อความ/ภาพให้ดู; ตอบถูกและไม่เลือกนับนิ้ว → ข้อความ P2 แล้ว "ต่อไป") | ครั้งเดียว | emit หลังเลือกในหัวเห็นอะไร |
| `guided-move` (B1) | 3 ขั้นต่อเนื่อง §5.2.2 | ดู §5.2.2 | emit ทุกครั้งที่ตอบ (`stepId`) |
| `teach-flash-make` (B3) | ready → show (`MakeTenBoard` แฟลช 2000: กล่อง + กองพร้อมกัน) → answering (`FieldGroup` 3 ช่อง หรือ 1 ช่อง) → หน้าเฉลย: กล่องเต็ม (ย้ายจุดให้ดูอัตโนมัติ: แสดงผลลัพธ์สุดท้ายทันที) + กองที่เหลือ + `NumberBond [ย้าย, เหลือ]` + ข้อความ (ถูก = P3, ผิด = ตามรหัสของขั้นแรกที่ผิด ลำดับ ขาด → เหลือ → ผลรวม) → "ต่อไป" | ครั้งเดียว | emit ตอน SUBMIT (มี `subAnswers`) |

**หมายเหตุร่วมของหน้าเฉลย/ข้อความ:** ไม่มีเสียง ไม่มีตัวเลขเวลา ไม่มีคำว่า "ผิด" หรือ "ผิดพลาด" (ใช้ข้อความ LS/ข้อเสนอเท่านั้น); ผู้ใช้กด "ต่อไป" เอง (ไม่มีเวลาบังคับ) ตัวเลือก "ในหัวเห็นอะไร" แตะเดียวแล้วไปต่อ (เหมือน DX-ADD); `strategyLatencyMs` วัดจากหน้านั้นแสดงจนเลือก

#### 5.2.1 A1 (`guided-fill`) รายละเอียด

- ตอบพร้อมกับแตะช่องได้ (ไม่ต้องเติมเต็มก่อนตอบ) แตะช่อง `empty` → `added` (สีใหม่) `NumberBond` ช่องกลาง = จำนวนช่องที่แตะ (`?` เมื่อยังไม่แตะ) แตะช่อง `dot` หรือ `added` ไม่มีผล (ไม่มีการยกเลิก) ผู้เรียก (`LessonPlayer`) เก็บ `added` เอง
- ตอบผิด: ข้อความตามรหัส `classifyLessonAnswer('gap', …)` — L1: LS ("นั่นคือจุดที่มีอยู่ ลองดูช่องที่ยังว่าง") ไฮไลต์ **ช่องที่ว่างตอนเริ่ม (index n..9)** ทั้งหมด (แม้ลูกแตะเติมไปแล้ว) · M5: LS ("ลองดูทีละแถว แถวบนเต็ม 5 แล้ว แถวล่างมีอีกกี่ช่อง") ไฮไลต์ชุดเดียวกัน · M4/MX: P4/P5 ไฮไลต์ชุดเดียวกัน ให้แก้ตอบใหม่ได้
- ตอบผิดครบ **3 ครั้ง** → เฉลยให้ (เติมช่องที่เหลือ + ข้อความถูก) และบันทึก `revealed: true` (Designer รับรองแล้ว Q6 ตัวเลข 3 เป็นค่าใน content)

#### 5.2.2 B1 (`guided-move`) 3 ขั้น

| ขั้น | จอ | ต้องทำ | ตอบผิด |
|---|---|---|---|
| 1 `gap` | `MakeTenBoard` ค้างไว้ (กล่อง a + กอง b, ยังไม่ให้ย้าย) + คำถาม "กล่องขาดอีกกี่ช่องถึงเต็ม" + แป้น | พิมพ์ 2 / 1 / 3 | `gap` rules |
| 2 `move` แล้ว `rest` | เปิดให้ย้ายจุดจากกอง (ลาก/แตะช่อง) จนกล่องเต็ม → ขึ้น `NumberBond [ย้าย, ?]` whole = b และคำถาม "เหลือในกองกี่จุด" + แป้น | ย้ายจนเต็ม (ไม่ต้องตอบระหว่างย้าย) แล้วพิมพ์ 3 / 5 / 1 | `rest` rules: M7 → LS ("ในกองยังมี {b} จุดหรือเปล่า ตอนนี้ย้ายไป {gap} แล้ว เหลือกี่จุด") + ไฮไลต์กองที่เหลือ; M5 → P6 + ไฮไลต์กองที่เหลือ; MX → P5 |
| 3 `total` | กล่องเต็ม 10 + กองที่เหลือ + คำถาม "10 กับ {เหลือ} ได้เท่าไร" + แป้น | พิมพ์ 13 / 15 / 11 | `total` rules: M7 → ข้อความ M7 LS ของ B1 (ข้อความเดียวกับขั้น rest พร้อมแสดงกองที่เหลือ); M6 → LS ("นั่นคือส่วนที่เหลือ อย่าลืมกล่องที่เต็ม 10 แล้ว") แสดงกล่องเต็ม + กองเหลือ; M5 → P6 ไฮไลต์กองที่เหลือ; MX → P5 |

- ขั้นถัดไปโผล่หลังตอบถูกขั้นก่อนเท่านั้น (LS §4 B1) ตอบผิดแก้ได้ใหม่จนครบ 3 ครั้ง แล้วเฉลยให้ (`revealed: true`) ตอบถูกขั้น 3 → ข้อความถูก LS ตรงตัวอักษร (เติมค่า) → "ต่อไป"
- ขั้นที่ 2 ที่ไม่ผ่านการย้าย: ถ้าลูกกดตอบเลขก่อนย้ายเต็มไม่ได้ (แป้นปิดจนกล่องเต็ม)

#### 5.2.3 B2 (`compare-start`, 4+9 และ 9+4)

1. หน้าเปิด: โจทย์ `4 + 9` และตัวเลือกวิธีตั้งต้น 2 แบบเคียงกัน (แบบ ก: `MakeTenBoard` กล่อง 4 + กอง 9 · แบบ ข: กล่อง 9 + กอง 4) ที่ 360px เรียงบนลงล่างและเลื่อนได้ในหน้า (ไม่ scroll แนวนอน)
2. ลูกย้ายจุดในทั้ง 2 แบบจนเต็ม ทางเดียวกับ B1 (ลาก/แตะ) ระบบขึ้น "ย้ายไป {k} จุด" ต่อแบบ (6 กับ 1) และผลเมื่อเต็ม (`เหลือ {r} 10 กับ {r} ได้ {t}`) ทั้งคู่ 13
3. เมื่อทั้ง 2 แบบเต็ม ขึ้นคำถาม LS 2 ข้อทีละข้อ (`OptionGrid`, P9): "ทั้งสองแบบได้เท่ากันไหม" (เฉลย ได้เท่ากัน) → "แบบไหนย้ายน้อยกว่า" (เฉลย เริ่มจาก 9) ตอบผิดแก้ได้ ≤ 3 ครั้งแล้วเฉลย
4. ข้อสรุปกฎ B: `เริ่มจากตัวที่ใกล้ 10 กว่า จะย้ายน้อยกว่า` (LS) → "ต่อไป"
- บันทึก `item.answered` ของ `B2.q1` และ `B2.q2` (โจทย์ `4+9`, ตัวเลือกเป็น `Choice.value`: q1 เท่ากัน=1 ไม่เท่ากัน=2; q2 เริ่มจาก 4=4 เริ่มจาก 9=9) พร้อม `manip` (จำนวนย้าย/ลาก/ถูกปฏิเสธ)

#### 5.2.4 ข้อสรุปกฎและหน้าอื่น

- `rule`: ข้อสรุปกฎ A (`ช่องที่เต็ม + ช่องที่ว่าง = 10 เสมอ ดูช่องว่างก็รู้คำตอบ`) ต่อท้าย A3; ข้อสรุปกฎ B ต่อท้าย B4 (LS §4) ตรงตัวอักษร พร้อมปุ่ม "ต่อไป"
- `tell-parent`: หลัง B4: "เล่าให้พ่อฟัง 1 ข้อ ว่าทำยังไง (ไม่ใช้จอ)" (ข้อความ LS §4 B4) + ปุ่มรับทราบ (ไม่บันทึกอะไร)

### 5.3 เกณฑ์ผ่าน การข้าม และการทำซ้ำ (`engine/lesson/evaluate.ts`, `plan.ts`)

นิยามใช้ร่วม: ข้อ "เร็ว" = ถูก **และ** (`latencyValid === false` **หรือ** `latencyMs ≤ เกณฑ์`) ตามกฎเดียวกับ DX-ADD (แท็บถูกซ่อน = ผ่านเกณฑ์เวลาถ้าถูก) เกณฑ์เวลามาจาก `skills.ts` (`noCountMs`)

| การตัดสิน | เงื่อนไข (ตรง LS) |
|---|---|
| **ข้าม A1+A2** (ไป A3) | เช็คก่อน c1–c3 ถูกหมด และแต่ละข้อ ≤ `add.bonds-10.noCountMs` (5000) |
| **ข้าม B1+B2** (ไป B3) | c4–c6 ถูกหมด และแต่ละข้อ ≤ `add.make-10.noCountMs` (8000) |

| **ผ่านส่วน B** | B4 ถูก ≥ 5/6 และมี ≥ 4 ข้อที่ "เร็ว" (≤ 8000) |
| **ผ่านแบบกำลังไปได้ดี** (B เท่านั้น) | ไม่ผ่านตามข้างบน แต่ค่าเฉลี่ย `latencyMs` ของ B4 ≤ 0.8 × ค่าเฉลี่ยของ **B3 ข้อ 4–6** (ลดลง ≥ 20% เทียบข้อที่พิมพ์ช่องเดียวเหมือนกัน LS §9) **และ** ไม่มีรหัส L1, M6, M7 ใน B3 และ B4 ของรอบนั้น (ค่าเฉลี่ยเฉพาะข้อที่ `latencyValid`) → นัดทบทวนที่กล่อง 1 |
| **ไม่ผ่าน A** | A3 ไม่ถึงเกณฑ์ |
| **ไม่ผ่าน B** | ไม่ผ่านและไม่เข้าเงื่อนไขกำลังไปได้ดี |
| **แจ้งพ่อ (ธง `tray-B1`)** | ใน B3+B4 ของรอบมีข้อที่ตอบผิดเป็น M6 หรือ M7 รวม ≥ 2 ข้อ |

**ลำดับหลังไม่ผ่าน** (LS §9; ส่วนที่เกิน LS Designer รับรองแล้ว (Q4))

| กรณี | ทำอะไร |
|---|---|
| ไม่ผ่าน A | ทำ A2 ซ้ำ 1 รอบด้วยชุดตัวเลขใหม่ (6 ข้อ, `generateA2Retry`) → หน้าพ่อ: ให้พ่อทำ Number Talks ด้วยถาดไข่จริง → จบครั้ง → **ครั้งถัดไปเริ่มด้วย A3 ชุดใหม่ (`generateA3Retry`)** เพื่อวัดผ่านซ้ำ ผ่าน → ไป B; ไม่ผ่านซ้ำ → แจ้งพ่อและแจ้ง Designer (ธง `stalled-A`) และ **เปิด B ให้เล่นต่อได้** (พ่อตัดสินใจ) |
| ไม่ผ่าน B | ทำ B3 ซ้ำ + B4 ซ้ำด้วยชุดใหม่ (`generateB3Retry`, `generateB4Retry`) **ไม่เกิน 2 รอบ** ถ้ายังไม่ผ่าน → ย้อนไป A3 อีกรอบ (ชุดใหม่) แล้วแจ้ง Designer (ธง `stalled-B`) ส่วน B ของบทหยุดรอ (ปุ่ม "เริ่มส่วน B ใหม่" อยู่ที่หน้าพ่อ) |

| ผ่านแล้ว | ไป block ถัดไปตาม `sittings` (ผ่าน A → จบครั้ง 1, ผ่าน B → ฝึกให้คล่อง → ท้าทาย) |

### 5.4 ตัวเล่นบทเรียน (`engine/lesson/machine.ts`, pure)

โครงเดียวกับ `machine.ts` ของ DX-ADD: `createLessonMachine(lesson, plan)` → `{ initial(), transition(state, action) → { state, effects } }` effects เป็น `emit` (event ที่ยังไม่มี id/at/…) และ `schedule` (ready 900, ack 1000, reveal) ทำใน `dispatch` ครั้งเดียวนอก `setState` (บทเรียน M1) `LessonPlayer` ใช้ `useActivityRunner` + `useTapGuard`

Phase หลัก (รายละเอียดภายในให้ Developer แต่ต้องมีครบและไม่ emit ซ้ำ)

```ts
type LessonPhase =
  | { kind: 'sitting-intro' }                                  // เปิดครั้ง (ปุ่มเริ่ม) → emit session.started
  | { kind: 'block-intro'; blockIdx: number }                  // ข้อความเปิดส่วน + "ไปเลย" → emit block.started
  | { kind: 'item'; blockIdx: number; itemIdx: number; stage: ItemStage }   // ตาม flow §5.2
  | { kind: 'rule'; text: string } | { kind: 'compare-start'; ... } | { kind: 'tell-parent' }
  | { kind: 'challenge'; step: 'intro' | 'play' | 'ask' | 'reveal' }
  | { kind: 'block-end'; blockIdx: number }                    // ตัดสินผ่าน/ไม่ผ่าน emit block.completed แล้วไป block ถัดไปหรือคำแนะนำ
  | { kind: 'parent-instruction'; reason: 'talk-A' | 'tray-B1' | 'stalled' }
  | { kind: 'handover' } | { kind: 'parent-note'; blockIds: string[] }
  | { kind: 'sitting-end' } | { kind: 'stopped' };
```
- `STOP` (พ่อกดค้างโลโก้ยืนยันหยุด): ก่อนเริ่ม → ไม่มี event; หลังเริ่ม → emit `session.abandoned`; block ที่ยังไม่จบไม่มี `block.completed`; ข้อที่ตอบแล้วแต่ยังไม่ผ่านคำถามในหัวเห็นอะไรไม่ถูกบันทึก (เหมือน DX-ADD D5)
- **พ่อข้ามส่วน:** กล่องยืนยันหยุดของพ่อ (กดค้างโลโก้ 2 วินาที) มีปุ่มที่ 2 `ข้ามส่วนนี้` เฉพาะ block ที่ข้ามได้ (`A`, `B`, `challenge`, `practice`) → emit `block.completed` `outcome: 'skipped'`, `skipReason: 'manual'`; ผลเช็คก่อนที่ข้าม A1/A2 หรือ B1/B2 ไม่ใช่การข้าม block แต่เป็น step ที่ไม่อยู่ใน plan (`skipReason: 'check'` บันทึกใน `block.started.skipped`)
- ห้ามแสดงถูก/ผิด คะแนน เวลา ในหน้าของลูกที่เป็น flow เงียบ (`silent-*`) รวมถึง block `check`, `practice`, `review`, `drill`; flow สอน (`guided-*`, `teach-*`, `mind-*`) แสดงข้อความ feedback ตาม LS แต่ไม่มีเวลา/คะแนนตัวเลข

### 5.5 ความก้าวหน้าของบท (`deriveProgress`)

อ่านจาก `block.completed` ล่าสุดของแต่ละ `kind`/รอบ (ไม่นับ block ที่ไม่จบ):

| ผลลัพธ์ที่คำนวณ | จาก |
|---|---|
| `checkDone`, ผลเช็คก่อน (ข้าม A1/A2 ไหม, ข้าม B1/B2 ไหม) | `block.completed` ของ `check` + `item.answered` ของ block นั้น |
| สถานะ A / B: `todo` `passed` `passed-trend` `not-passed` `stalled` `skipped` และ `retryRound` | `block.completed` ของ A / B (`outcome`, `round`) |
| ธงพ่อที่ค้าง: `talk-A`, `tray-B1`, `stalled-A`, `stalled-B`, กลุ่มรีเซ็ต Leitner (L1/M4/M6/M7 ในรอบทบทวน) | `block.completed.next`/`flags` + `engine/leitner.ts` |
| ครั้งที่ปัจจุบัน (`sitting`) | จำนวน `session.completed` ของ `lessonId` + 1 |
| ท่องซ้ำเปิดหรือยัง | `isDrillUnlocked()` §5.6.4 |

### 5.6 ฝึกให้คล่อง ทบทวน Leitner และท่องซ้ำ

#### 5.6.1 รอบฝึก (`practice`, `review`)

- รอบ = 4 ข้อจาก generator ของทักษะนั้น flow เงียบ (ตอบ → ack) ถาม "ในหัวเห็นอะไร" (ชุด `add.mind-view` มีปุ่ม `ข้าม`) **เฉพาะข้อสุดท้ายของรอบเท่านั้น** ไม่ถามทุกข้อ (LS §6.2 ตัดสินแล้ว Q9) ข้ออื่นอีก 3 ข้อ emit ตอน SUBMIT ตามปกติ ข้อสุดท้าย emit หลังเลือกหรือกด "ข้าม" (`mindView` ว่างเมื่อข้าม) ส่วน A3/B4 ในบทยังถามทุกข้อตาม LS §4 จบรอบแสดงข้อความ LS §6.3 ผ่าน `roundSummary()` เท่านั้น
- `practice` (ในบท ครั้งที่ 2 หลังผ่าน B): 1 รอบ bonds + 1 รอบ make-ten (รวม 8 ข้อ) **ไม่เลื่อนกล่อง** (บันทึกเป็นการฝึก; ทักษะเข้า Leitner ตอนผ่านส่วนที่สอนทักษะนั้น)
- `review` (นอกบท, Home การ์ด "ทบทวนวันนี้" เมื่อมีทักษะครบกำหนด): 1 รอบต่อทักษะที่ครบกำหนด; ถ้าครบกำหนดทั้ง 2 ทักษะในวันเดียวกัน ทำต่อกัน bonds → make-ten (≤ 3 นาที/รอบ ตาม LS §6.2 ไม่บังคับด้วยเวลา)
- **ข้อความจบรอบ (`roundSummary(current, previous)`)**: ไม่แสดงเวลา คะแนนดิบ หรือ "ช้า" ถ้ามีรอบก่อนของทักษะเดียวกัน (`block.completed` ล่าสุดของทักษะนั้นที่เป็น `practice`/`review`) `k` = จำนวนข้อของรอบนี้ที่ **ถูกและ `latencyMs` น้อยกว่าค่าเฉลี่ย `latencyMs` ของข้อถูกในรอบก่อน** (เฉพาะ `latencyValid`) ถ้า `k ≥ 1` → `วันนี้เร็วกว่าครั้งก่อน {k} ข้อ` มิฉะนั้น `วันนี้ทำครบ {n} ข้อ` (`n` = จำนวนข้อ)

#### 5.6.2 Leitner (`engine/leitner.ts`, pure, ADR-0006)

```ts
export interface SkillReviewState { skillId: SkillId; box: 1 | 2 | 3 | 4 | 5; dueDate: string /* YYYY-MM-DD ท้องถิ่น */; lastAt: string; flags: { at: string; misconceptionId: string; itemId: string }[] }
export function computeReviewStates(events: readonly AppEvent[], skills: readonly Skill[], learnerId: string): SkillReviewState[];
export function dueSkills(states: readonly SkillReviewState[], now: Date): SkillId[];
```
คำนวณจาก log ทุกครั้ง (เรียงด้วย `compareEvents`) ต่อทักษะที่มี `review`

1. **เข้าระบบ:** เมื่อ `block.completed` ของ block ที่สอนทักษะนั้นมี `outcome` = `passed` หรือ `passed-trend` (A → `add.bonds-10`, B → `add.make-10`) → `box = 1`, `dueDate = วันที่ท้องถิ่นของ at + intervalsDays[0]`
2. **แต่ละรอบทบทวน** (`block.completed` ที่ `kind: 'review'` ของทักษะนั้น เรียงตามเวลา) ใช้ `item.answered` ที่มี `blockId` เดียวกัน:
   - มีข้อที่ `misconceptionId ∈ review.resetOn` → `box = 1` และเพิ่ม `flags` (แจ้งพ่อ)
   - ไม่งั้น หาระดับตามกล่องปัจจุบัน `level = boxLevels[box − 1]` (`noCount` → `fluency.noCountMs`, `automatic` → `fluency.automaticMs`) นับ **ข้อที่ถูกและเร็วตามระดับนั้น** (แท็บซ่อนและถูก = เร็ว) ถ้านับได้ ≥ `round.minFluent` (3) → **คล่อง** → `box = min(5, box + 1)`; ไม่ถึง → `box = max(1, box − 1)`
   - `dueDate = วันที่ท้องถิ่นของ at + intervalsDays[box − 1]`
3. `dueSkills(states, now)`: `วันที่ท้องถิ่นของ now ≥ dueDate`
4. **ตัดสินแล้ว (Q3):** (ก) "ถูก ≥ 3 จาก 4 ข้อ และเวลาอยู่ในระดับ" = ≥ 3 ข้อที่ **ทั้งถูกและเร็ว** (ก) ความคล่องตัดสินตาม LS §6.1 เท่านั้น (ข) LS §6.2 แก้แล้ว: M5/MX **ไม่รีเซ็ตกล่อง** เช่น ถูกและเร็ว 3 ข้อ ผิด M5 1 ข้อ = คล่อง ถ้าถูกและเร็วไม่ถึง 3 ข้อ ถอย 1 กล่องตามปกติ
5. ธงแจ้งพ่อ (`flags`) แสดงในหน้าพ่อ ไม่แสดงลูก

**เทสต์ Leitner (unit, `leitner.test.ts`)** วันที่ตั้งด้วยเวลาท้องถิ่นเสมอ (ไม่พึ่ง UTC) ตารางสถานการณ์อย่างน้อย
| # | สถานการณ์ (bonds) | ผลที่ต้องได้ |
|---|---|---|
| L-1 | ผ่าน A วันที่ 0 | box 1, due วัน 1 |

#### 5.6.3 หน้าหลัก

การ์ดตามลำดับ: บท ADD-04 (ครั้งที่/ทำครบแล้ว) · `ทบทวนวันนี้` (แสดงเฉพาะเมื่อ `dueSkills` ไม่ว่าง) · `ท่องซ้ำ 2 นาที` (เฉพาะเมื่อปลดล็อก) · DX-ADD เดิม ไม่มี badge จำนวนหรือเวลา (ห้ามกดดัน)

#### 5.6.4 ท่องซ้ำ (Kumon, LS §8)

- `isDrillUnlocked(events)`: ผ่านส่วน A **และ** รอบ `review` ของ `add.bonds-10` **2 รอบล่าสุดติดกัน** แต่ละรอบถูก ≥ 3/4 และมี ≥ 3 ข้อที่ถูกและ ≤ `automaticMs` (3000 ms; แท็บซ่อนและถูก = เร็ว)
- `DrillPlayer`: ชุดคู่รวม 10 ตัวเลข 1–9 (รวม 5) ทุกตัวปรากฏ 1 ครั้งต่อรอบสับไพ่ ถามทีละใบเป็น `n + ? = 10` หรือ `? + n = 10` (สุ่มตำแหน่ง) ตอบด้วยแป้น flow เงียบ; เมื่อครบ 9 ใบสับใหม่ต่อไปจนเวลารวมถึง **2 นาที** (นับเงียบ เช็คที่ขอบข้อ ไม่แสดงนาฬิกา ไม่มีแถบเวลา) จบแล้วแสดง `วันนี้ทำครบ {n} ข้อ` ไม่เปิดคู่รวม 20
- บันทึก `item.answered` (`blockId` ของ `block.started` ชนิด `drill`) และ `block.completed` `outcome: 'done'`; ไม่มีผลต่อกล่อง Leitner

### 5.7 หน้าสำหรับพ่อ

**หน้าส่งเครื่องและบันทึกของพ่อ (`parent-note`)** ปลายครั้ง (หลังจบ block สุดท้ายของครั้ง): หน้า `handover` (ให้ลูกส่งเครื่อง) → หน้าพ่อ: ข้อความสรุปสั้นๆ (ผ่านหรือไม่ต่อส่วน, ธงที่ต้องทำ เช่น ถาดไข่) + ฟอร์ม **บันทึกของพ่อ** ต่อส่วนที่สอนในครั้งนั้น (A ในครั้งที่ 1, B ในครั้งที่ 2): `ใช้นิ้ว` และ `ขยับปากนับ` แต่ละอันเลือก `ไม่ใช้ / บางข้อ / เกือบทุกข้อ` + โน้ตสั้น (≤ 200 ตัวอักษร ไม่บังคับ) ปุ่ม `บันทึก` (emit `parent.noted`) หรือ `ข้าม` (ไม่ emit) ทำภายหลังจากหน้า `/parent/lesson/ADD-04` ได้ (บันทึกซ้ำ = event ใหม่ ค่าล่าสุดคือค่าปัจจุบัน ADR-0008 ข้อ 5)

**หน้า `/parent/lesson/ADD-04`** (เข้าจาก `/parent`): เรียงบนลงล่าง
1. ความก้าวหน้า: ครั้งที่, ผลแต่ละส่วน (ผ่าน/กำลังไปได้ดี/ยังไม่ผ่าน/ข้าม พร้อมเหตุผลข้าม), ระดับคล่อง, กล่อง Leitner และวันครบกำหนดต่อทักษะ (เวลาแสดงเฉพาะหน้านี้)
2. ธงที่ต้องทำ: `talk-A`, `tray-B1`, `stalled-A`/`stalled-B` (แจ้ง Designer), รหัสที่ทำให้กลับกล่อง 1 พร้อมข้อและวันที่ ปุ่ม `ทำแล้ว` (emit `parent.noted` ประเภทธง) และ `เริ่มส่วน B ใหม่`
3. ของจริงที่พ่อควรเตรียม (LS §4) และ Number Talks (LS §5: โจทย์, คำถามเปิด, วิธีคิดที่อาจได้ยินและวิธีตอบ, สิ่งที่ไม่ควรพูด) ตรงตัวอักษร
4. คำถามต่อยอดปริศนา 1–10 พร้อมเฉลย (LS §7)
5. บันทึกของพ่อทั้งหมด (ล่าสุดต่อส่วน) และฟอร์มแก้
6. รายละเอียดทุกข้อ (ตารางเหมือน DX-ADD §5.7: ข้อ, ส่วน, โจทย์, คำตอบ, ถูก/ผิด, เวลา วินาที 1 ตำแหน่ง, คล่อง, "ในหัวเห็นอะไร", ความเข้าใจผิด, ขั้นย่อย) เลื่อนแนวนอนภายในกล่องตารางที่ 360px

## 6. ข้อมูลที่บันทึก

ตาม ADR-0003 และ ADR-0008: `schemaVersion` ยัง **1** (เพิ่ม field เสริมและชนิดใหม่เท่านั้น) `at` เพิ่มขึ้นเคร่งครัดต่อ session (ตัวประทับของ DX-ADD §14.2) และ `isAppEvent` ตรวจ field/ชนิดใหม่ทั้งหมดพร้อมเทสต์ (`migrations.test.ts`)

### 6.1 Event

- ไม่บันทึกชื่อจริง (`note` เป็นข้อความอิสระของพ่อ อยู่ในเครื่องและไฟล์ export เท่านั้น ห้าม commit ไฟล์ export)
- ลำดับ: `session.started` → `block.started` → `item.answered`… → `block.completed` → … → `parent.noted` → `session.completed` ตามลำดับชนิดของ ADR-0008 (`parent.noted` อยู่ก่อน `session.completed` เมื่อทำก่อนจบครั้ง) `review` และ `drill` เป็น session ของตัวเอง (`activityId: 'ADD-04'`, `sitting` ไม่มี)
- ข้อที่ผู้เล่นตอบใน block ที่ไม่จบ ยังอยู่ใน log แต่ไม่เข้าการคำนวณ (§5.1)

### 6.2 การเขียน event

- เขียนผ่าน outbox (M0) เหมือน DX-ADD; ชุด event ของ transition เดียว append ครั้งเดียว
- **ห้ามเขียน event ใน `setState` updater** (บทเรียน M1) ต้องทดสอบทั้ง `npm run dev` และ production build (e2e `E2E_DEV=1`)

### 6.3 เกณฑ์ผ่านและความเข้าใจผิดที่คำนวณจาก event

`engine/lesson/evaluate.ts` รับ `item.answered` ของ block (กรองด้วย `blockId` และ `attemptNo === 1` ของ `stepId` หลัก) คืน `BlockOutcome` ใช้เมื่อ block จบ (ค่าที่บันทึกใน `block.completed`) และหน้าพ่อคำนวณย้อนหลังจาก log ได้ (ไม่พึ่งค่าที่เก็บไว้เพียงอย่างเดียว)

## 9. สิ่งที่ Developer ต้องไม่ทำ

- **ห้ามเปลี่ยนโจทย์ เฉลย ข้อความ เกณฑ์ ตัวเลขชุดฝึก หรือรหัสความเข้าใจผิด** ถ้าเห็นว่าผิดให้แจ้ง (Developer → Architect → Designer) ข้อความที่ Designer รับรองใน §4.7 เปลี่ยนได้เฉพาะเมื่อ Designer แก้
- ห้ามแสดงเวลา นาฬิกา แถบเวลา คะแนนดิบ หรือคำว่า "ช้า" ในหน้าของลูก; flow เงียบ (`silent-*`) ห้ามบอกถูก/ผิดด้วย ข้อความ สี เสียง สั่น หรือ animation
- ห้ามใช้คำว่า "ยืม", "เก่ง", "ง่าย" ในข้อความของลูก
- ห้ามเปลี่ยนเวลาแฟลช (900 / 1500 / 2000) ตาม reduced motion หรืออุปกรณ์
- **ห้ามทำ side effect (emit event, ตั้ง timer) ภายใน `setState` updater** ใช้ `useActivityRunner`
- ห้ามคำนวณเฉลยจากค่าที่พิมพ์ไว้แทน `solve(problem)`/`makeTenPlan` ตอนใช้งานจริง และห้ามใช้ `Math.random()` ใน generator (ใช้ `createRng(seed)` เท่านั้น seed จากภายนอก)
- ห้ามใช้ `<circle>` กับสิ่งที่ไม่ใช่จุดใน `TenFrame`/`MakeTenBoard`
- ห้ามตั้ง `touch-action: none` ทั้งหน้า (เฉพาะ element ที่ลาก) และห้ามทำให้การลากเป็นทางเดียว (ต้องมีทางแตะเสมอ)
- ห้ามเขียน store ตรงจากหน้าจอ ต้องผ่าน outbox; ห้ามลบหรือแก้ event ใน log
- ห้ามใช้ภาพการ์ตูน มาสคอต หรืออีโมจิแบบเด็กเล็ก
- ห้ามแก้พฤติกรรมของ DX-ADD ตอนแยก `useTapGuard`/`useActivityRunner`/`useFlash` (เทสต์เดิมต้องผ่านโดยไม่แก้)
- ห้าม commit/push (ผู้ประสานงานเป็นคน commit)
