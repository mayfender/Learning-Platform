### BUG-DX-ADD-01: แตะตัวเลือก "หนูคิดยังไง" ซ้ำ แล้วการแตะที่สองไปกดตัวเลขในข้อถัดไป (ข้อมูลคำตอบผิด)
- ระดับ: **Major** (ทำให้คำตอบที่บันทึกผิดได้ ถ้าเด็กแตะซ้ำ ไม่ใช่ทุกครั้ง)
- อ้างอิง spec: Tech Spec §3.3 "กันแตะซ้ำหลังเลือก", roles/tester.md §6.5 "แตะเร็วๆ ติดกันหลายครั้ง", §7 ("เฉลยหรือการตัดสินผิด ข้อมูล…ผิด")
- สภาพแวดล้อม: production และ dev (ก่อนลดขอบเขต), project `android-tablet` (712x1138), `phone` (412x839), `ipad` (810x1080) — ไม่เกิดที่ `desktop` (จอกว้าง ตัวเลือกไม่ซ้อนกับแป้น)
- ขั้นตอนทำซ้ำ:
  1. ทำถึงข้อ 3.3 (6 + 7) กด "ตอบ" จนถึงหน้า "หนูคิดข้อนี้ยังไง?"
  2. แตะ "จำได้เลย" สองครั้งห่างกัน 30–300 ms (จุดเดียวกัน)
  3. ดูช่องคำตอบของข้อ 3.4 (7 + 8)
  4. พิมพ์ 1 5 แล้วกด "ตอบ"
- ผลที่คาด: การแตะที่สองไม่ส่งผลกับหน้าถัดไป ช่องคำตอบว่าง; คำตอบข้อ 3.4 = 15 (ถูก)
- ผลจริง: ช่องคำตอบแสดง `1` ทันที (แตะที่สองไปโดนปุ่ม `1` ที่ตำแหน่งเดียวกัน) พิมพ์ต่อเป็น `115` (จำกัด 3 หลัก) จึงตอบ 115 → จะถูกบันทึกเป็นผิดและได้รหัส MX
- หลักฐาน: บน phone ตัวเลือก "จำได้เลย" กินพื้นที่ x=24–200, y=347–411 ซ้อนกับปุ่ม `1` (x=26–141, y=359–415) ของหน้าถัดไป; `typed()` หลังแตะซ้ำ = `"1"`; หลังพิมพ์ 15 ช่องแสดง `"115"`; เทสต์ TC-70d (150 ms) ล้มซ้ำได้ทุกครั้งบน 3 project (ก่อนลดขอบเขต TC-70b และ TC-70d 30/300 ms ล้มเหมือนกัน)
- ข้อเสนอ (ไม่ใช่การแก้เอง): ให้หน้าใหม่เพิกเฉยต่อ pointer event ช่วงสั้นๆ หลังเปลี่ยนหน้า (เช่น 300–400 ms) หรือแยกตำแหน่งตัวเลือกกับแป้น ที่ "ไปเลย" และ "ตอบ" ทดสอบแล้วไม่เกิด

### BUG-DX-ADD-02: dark mode ขั้นบันไดที่ไฮไลต์ในหน้าผลของพ่ออ่านไม่ออก
- ระดับ: **Major** (AC13 ระบุ dark mode ต้องอ่านได้ชัด; ข้อมูลหลัก "ขั้นที่แนะนำ" ยังอ่านได้จากส่วนบนสุด จึงไม่ถึง Blocker)
- อ้างอิง spec: Tech Spec AC13 "dark mode อ่านได้ชัด", overview §6, roles/tester.md §6.3
- สภาพแวดล้อม: production และ dev; TC-12 ล้มทั้ง 4 project (android-tablet, phone, ipad, desktop) ที่โหมดมืด
- ขั้นตอนทำซ้ำ: 1. `emulateMedia({ colorScheme: 'dark' })` หรือใช้ธีมมืด 2. ทำภารกิจจนจบ (หรือใช้ชุด S01) 3. กด "ให้พ่อดูผล" 4. ดูส่วน "บันไดการบวก" บรรทัดที่ไฮไลต์ "← เริ่มตรงนี้"
- ผลที่คาด: ข้อความอ่านชัด (ความเปรียบต่าง ≥ 4.5:1)
- ผลจริง: ตัวอักษรสี `rgb(232, 240, 235)` บนพื้นไฮไลต์ `rgb(255, 212, 121)` ความเปรียบต่าง **1.21:1** (ตัวอักษรขาวอ่อนบนพื้นเหลือง) มองเห็นเป็นแถบเหลืองตัวหนังสือจาง; โหมดสว่างไม่พบปัญหา
- หลักฐาน: TC-12 รายงาน `results: 1.21 "ขั้นที่"` ทุก project; ภาพหน้าจอส่วนบันไดที่ 360px ใน dark mode ยืนยันด้วยตา; เทสต์ e2e ของ Developer ตรวจแค่สีพื้นหลัง (รายงานการพัฒนา AC13 อ้าง "dark mode (e2e 4)") จึงไม่พบ

### BUG-DX-ADD-03: ลิงก์ "กลับหน้าสำหรับพ่อ" ในหน้าผลสูงแค่ 27px
- ระดับ: **Minor** (หน้าของพ่อ ไม่ใช่หน้าของลูก)
- อ้างอิง spec: Tech Spec AC13 "ปุ่ม ≥ 48px", overview §6 "พื้นที่แตะ ≥ `--tap-min`" (ดูคำถาม Q5)
- สภาพแวดล้อม: ทุก project ที่ 360px (และทุกความกว้างเพราะเป็นลิงก์ข้อความ)
- ขั้นตอนทำซ้ำ: 1. ทำภารกิจจนถึงหน้าผล 2. วัดขนาดของลิงก์ "กลับหน้าสำหรับพ่อ" ใต้หัวข้อหน้า
- ผลที่คาด: พื้นที่แตะ ≥ 48px
- ผลจริง: กว้าง 131.5px สูง 27px (ปุ่มอื่นในหน้าเดียวกัน "ทำใหม่อีกครั้ง", "export", ลิงก์ประวัติ สูง 48–49px)
- หลักฐาน: TC-62 (`smallest-target` = `{"name":"กลับหน้าสำหรับพ่อ","w":131.5,"h":27}`)

### BUG-DX-ADD-04: กด Backspace ที่แป้นตัวเลขบน WebKit ทำให้เบราว์เซอร์ย้อนกลับหน้า
- ระดับ: **Minor** (ต้องมีคีย์บอร์ดจริง ลูกใช้แท็บเล็ตสัมผัส ผลกระทบต่ำ; ยังไม่ยืนยันบน Safari/iPad จริง)
- อ้างอิง spec: Tech Spec §3.2 "รับคีย์บอร์ดจริง: Backspace" (ดูคำถาม Q4)
- สภาพแวดล้อม: production และ dev; ตัวตรวจ `defaultPrevented` (TC-06c) ที่ desktop และสคริปต์แยก 1 ครั้งบน `ipad` (WebKit ของ Playwright) ก่อนลดขอบเขต
- ขั้นตอนทำซ้ำ: 1. เปิดข้อที่มีแป้น (เช่น 2.1) พิมพ์เลข 1 ตัว 2. กด Backspace บนคีย์บอร์ด
- ผลที่คาด: ลบตัวเลข 1 ตัว และอยู่หน้าเดิม
- ผลจริง: ตัวเลขถูกลบ **และ** เบราว์เซอร์ (WebKit) ย้อนกลับไปหน้าหลักทันที ออกจากภารกิจกลางทาง; เหตุ: ตัวจัดการคีย์ไม่เรียก `preventDefault()` (ตัวฟังของ Tester หลังแอปเห็น `defaultPrevented=false`)
- หลักฐาน: TC-06c ล้ม (desktop; ก่อนลดขอบเขตล้มทั้ง 4 project); สคริปต์แยก: หลังกด Backspace บน iPad URL เปลี่ยนจาก `#/play/DX-ADD` เป็นหน้าหลัก ขณะ desktop (Chromium) อยู่หน้าเดิม

### Suggestion (ไม่ผิด spec ชัดเจน ส่ง Architect/Designer พิจารณา)
- **S1 เนื้อหาเก่าค้างชั่วคราว:** ในหน้าผล เมื่อกดลิงก์ในส่วน "ประวัติ" เพื่อเปิดผลอีกครั้ง URL เปลี่ยนทันทีแต่เนื้อหาเดิมค้างอยู่ประมาณ 100–300 ms ก่อนเปลี่ยน (พ่ออาจเห็นผลผิดครั้งชั่วขณะ) ตรวจพบเพราะ TC-60 อ่านเร็วเกินไป ควรแสดงสถานะกำลังโหลดหรือล้างเนื้อหาเดิมเมื่อ `sessionId` เปลี่ยน
- **S2 ตัวฟังคีย์บอร์ดยังทำงานหลังกล่องยืนยัน:** ขณะกล่อง "หยุดภารกิจนี้?" เปิดอยู่ กดเลขบนคีย์บอร์ดยังพิมพ์ลงช่องคำตอบด้านหลัง (และ Enter น่าจะส่งคำตอบ) ผลกระทบเฉพาะคนที่มีคีย์บอร์ดจริง ควรปิดการรับคีย์ตอนมี dialog
- **S3 ปุ่มซ้อนในลิงก์:** "ทำใหม่อีกครั้ง" เป็น `<a><button>` (โครงสร้าง HTML ที่ไม่ถูกต้อง ทำให้ Tab ได้ 2 ครั้งและโปรแกรมอ่านจอสับสน)

## 4. สิ่งที่ยังไม่ได้ทดสอบ และเหตุผล

- **อุปกรณ์จริงทั้งหมด** (แท็บเล็ต Android ของลูก, iPad จริง): ไม่มีอุปกรณ์ในสภาพแวดล้อมนี้ → เช็คลิสต์ข้อ 6
  - ความชัดของภาพแฟลชด้วยตา, ขนาดจุด, ความสว่างจอ
  - การแตะด้วยนิ้วจริง (การแตะซ้ำแบบ BUG-01 ควรลองบนเครื่องจริงด้วย) และการกดค้างโลโก้ด้วยนิ้ว (ทดสอบด้วยเมาส์จำลองเท่านั้น; เมนู context/เลือกข้อความของเบราว์เซอร์มือถือยังไม่ได้ดู)
  - หมุนจอด้วยเซ็นเซอร์จริง (ทดสอบด้วยการสลับขนาด viewport)
  - Safari/iPad จริง (ใช้ WebKit ของ Playwright แทน; BUG-04 ยังไม่ยืนยันบน Safari จริง)
- **ติดตั้ง PWA และ offline จริง** (M0 AC7): ทดสอบแค่ service worker ใน Chromium (TC-74)
- **การสลับแอป/พับจอจริง:** จำลองด้วยเหตุการณ์ `visibilitychange` เท่านั้น
- **เคสตรรกะ/ข้อมูลบน android-tablet, phone, ipad** (ชุดข้อมูลระดับ-ขั้นแนะนำ, ตาราง "คำตอบผิด" 24 รอบ, หยุดกลางทาง, ประวัติ, import/export รอบเต็ม, ข้อความทุกหน้า, ปุ่ม back/reload/offline ฯลฯ) และ dev server ยกเว้น TC-20: ไม่ได้รันบนอุปกรณ์เหล่านี้ เหตุผล "ลดขอบเขตตามที่พ่ออนุมัติ: ตรรกะไม่ขึ้นกับอุปกรณ์" (ก่อนลดขอบเขตชุดเต็มเคยรันทุก project แล้ว 1 รอบ ผ่านเหมือน desktop ยกเว้นบั๊กที่รายงาน)
- **การแตะซ้ำที่ "ไปเลย"/"ตอบ" ที่ระยะห่าง 30 และ 300 ms และ TC-70b บนอุปกรณ์สัมผัส:** ตัดออกหลังลดขอบเขต (ผลก่อนหน้าเหมือน 150 ms)
- **ตัวอ่านหน้าจอ/การเข้าถึงเชิงลึก**: ไม่ได้ทดสอบ (ตรวจแค่ role/aria-label ที่ spec กำหนด)
- **เบราว์เซอร์อื่น** (Firefox, Safari macOS, Edge): นอกขอบเขต 4 project
- **ตัวจับเวลาที่เกิดจากความช้าของเครื่องจริง:** ใช้นาฬิกาปลอมเป็นหลัก มีเคสเวลาจริง 4 เคส (TC-08, 61, 73, 80) แต่ไม่ได้ทดสอบบนเครื่องช้า
- **ข้อความ/สีเชิงสุนทรียภาพ:** ไม่ใช่งานของ Tester (Designer ตรวจ)
- **การทดสอบซ้ำหลังแก้ (regression):** ยังไม่มี (รอบแรก)

## 5. สรุปคำแนะนำ

**ปล่อยไม่ได้ในรอบนี้** เพราะมี Major 2 ข้อ (ตามกติกา §7 ห้ามปล่อยยกเว้นพ่ออนุมัติ)
1. BUG-DX-ADD-01 (Major): แตะซ้ำที่ตัวเลือกวิธีคิดบนอุปกรณ์แนวตั้งทำให้มีเลขค้างในข้อถัดไปและอาจบันทึกคำตอบผิด — ควรแก้ก่อนให้ลูกใช้เพราะเด็กแตะซ้ำได้ง่ายและผลวินิจฉัยจะเพี้ยนโดยไม่รู้ตัว
2. BUG-DX-ADD-02 (Major): dark mode ขั้นที่ไฮไลต์ในหน้าผลอ่านไม่ออก — แก้สีตัวอักษรบนพื้นไฮไลต์ (ผลกระทบต่อพ่อเท่านั้น ถ้าพ่อยืนยันว่าจะใช้โหมดสว่างระหว่างนี้ อาจอนุมัติปล่อยเป็นข้อยกเว้นได้)

ส่วนที่ผ่านอย่างชัดเจนและเชื่อถือได้: คณิตศาสตร์และการตัดสินทั้งหมด (123 คู่คำตอบผิดกับวิธีคิด, ระดับ, กลุ่ม 5A–5C, ขั้นที่แนะนำทั้ง 9 แถว, กรณีหยุดกลางทาง, กฎข้ามด่าน 5), จำนวน event ตรงเป๊ะ 22 (1/20/1) ทั้ง dev และ production, จังหวะแฟลชและจำนวนจุดตรง spec ทุกข้อ, ไม่มีเวลา/คะแนน/ถูก-ผิด/เสียง/สั่นในหน้าของลูก, หน้าตาของลูกเหมือนกันไม่ว่าตอบถูกหรือผิด, ไม่มี request ภายนอก, ข้อมูลอยู่หลัง reload และ export/import ไม่ซ้ำ

ตามกติกา ต้องกลับไป Developer แก้ BUG-01, BUG-02 (และควรแก้ BUG-03, BUG-04 ไปพร้อมกัน) แล้ว Tester ทดสอบซ้ำ (เคสที่ต้องรันซ้ำ: TC-70d, TC-12, TC-62, TC-06c และ regression ตามขอบเขตที่ลด) ก่อนส่ง Architect/Designer
